# Keepsake · 我们仨

Keepsake 是一个面向一家三口的家庭记忆站，用于长期保存旅行照片、Bilibili 视频、生活文章和家庭日常。

项目以安静的阅读体验、响应式相册和本地媒体隐私为核心，目前同时支持卡片与时间轴两种浏览方式。

## 核心能力

- 首页展示相册数量、精选相册、旅行影像和最新文章
- 相册采用“全部显示封面、进入后显示照片”的两级浏览
- 相册与文章支持卡片、时间轴两种布局
- 图片运行时读取、方向校正、尺寸限制和 WebP 输出
- Bilibili 官方播放器嵌入，不在项目中存储视频文件
- Markdown 文章系统与中英文界面
- 亮暗主题、移动端导航、PWA 安装和离线缓存
- 相册收藏与浏览偏好保存在浏览器本地

## 架构

```text
Browser
  ↓
Nuxt pages + media API
  ↓
Local media library
  ├─ album photos
  ├─ banners
  ├─ video covers
  └─ article covers
```

前端不直接访问本地文件。服务端媒体接口负责路径校验、图片读取和 WebP 转换；相册信息由运行时媒体清单提供。

当前架构要求 Nuxt 服务运行在能够访问照片的电脑或家庭服务器上。纯静态平台无法访问家庭电脑中的图片，因此不能单独托管当前媒体功能。

## 媒体与内容模型

- 相册文件夹名称包含相册标题和上传日期
- 日期支持补零与非补零写法，接口统一返回标准日期
- 相册直接图片按 `001`、`002`、`003` 编号
- 非递归扫描私人目录，避免误读其他文件
- 首页横幅、视频封面和文章封面使用独立媒体用途
- 文章封面与视频元数据不硬编码在正文中

## 部署边界

当前版本不是纯静态网站。可接受的部署方式：

- 家庭电脑或 NAS 运行 Nuxt 服务
- Cloudflare Tunnel 或 Tailscale 提供 HTTPS 访问
- 保持媒体目录在线并定期备份

要继续向云端演进，建议增加：

- MySQL：相册、照片、文章、视频和权限元数据
- uniCloud、COS、OSS 或 NAS：媒体文件与缩略图
- 独立 API：鉴权、上传、签名访问和图片处理
- 管理后台：内容编辑、排序和软删除

更完整的演进方案见“文字记录”中的项目建议。

## 安全要求

- 不通过隐藏链接保护家庭照片
- 数据库与对象存储密钥不得进入浏览器
- 媒体访问必须经过服务端鉴权或短时效签名
- 不将 MySQL 或对象存储端口直接暴露到公网
- 共用设备上谨慎使用 PWA 离线缓存
- 原图、数据库和配置需要独立备份
