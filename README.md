# Keepsake · 我们仨

Keepsake 是一个面向一家三口的家庭记忆网站，用来收藏旅行照片、Bilibili 旅行影像、生活文章和值得长期保留的日常片段。

项目以阅读体验、照片浏览和家庭隐私为核心，目前已经具备完整的前端页面、本地媒体服务、相册浏览、文章系统和 PWA 能力。

## 当前重点

- “全部”相册页只展示每本相册的第一张封面
- 点击相册后，在原页面查看该相册的全部照片
- 相册名称和上传日期由媒体库目录自动识别
- 相册照片统一使用 `001`、`002`、`003` 编号
- 照片文件不复制到网站项目，由本地媒体服务实时读取
- 支持运行时图片读取、方向校正和 WebP 输出
- 首页展示相册数量、精选相册、旅行视频和最新文章
- 已接入一条 Bilibili 旅行视频
- 文字记录包含“项目说明”和“MySQL 升级建议”两篇文章
- 支持亮暗主题、中英文界面和移动端布局
- 支持 PWA 安装与静态资源缓存

## 页面结构

### 首页

展示家庭主视觉、相册数量、精选相册、旅行影像、最新文章和家庭宣言。

### 相册

默认只显示相册封面。选择具体相册后，在同一页面显示该相册的全部照片，并支持灯箱预览和本地收藏。

### 旅行影像

通过 Bilibili 官方播放器播放旅行视频。项目只保存视频索引，不存储视频文件。

### 文字记录

文章使用 Markdown 管理，目前包括：

- 项目说明：记录项目目标、功能、媒体方案和技术选型
- 项目建议：说明如何引入 MySQL、对象存储和后台管理

### 关于我们

介绍家庭近况、设计理念、项目边界和后续方向。

## 当前架构

```text
浏览器
  ↓
Nuxt 页面 / 服务端媒体接口
  ↓
本地媒体库
  ├─ 相册照片
  ├─ 横幅图片
  ├─ 视频封面
  └─ 文章封面
```

页面不会直接读取本地文件。浏览器通过受控媒体接口请求照片，服务端完成权限边界检查、图片读取、方向校正、尺寸限制和 WebP 转换。

这种方案适合家庭自用，但网站必须运行在能够访问照片的电脑或家庭服务器上。纯静态托管平台无法直接访问家庭电脑中的照片。

## 内容管理

### 相册规则

相册目录使用“相册标题 + 上传日期”的格式。日期支持补零和非补零写法，页面会统一显示为标准日期。

每本相册中的照片按数字编号排列，新增照片后建议继续使用三位编号。只读取相册目录中的直接图片，不递归扫描其他私人目录。

### 特殊图片

非相册图片通过固定用途目录管理：

- 首页横幅
- 旅行视频封面
- 文章封面

新增内容后刷新页面即可。媒体清单有短暂缓存，稍等片刻或重启开发服务即可更新。

### 旅行视频

当前只保留一条 Bilibili 视频。后续更换视频时，只需要更新视频编号、标题和说明，不需要存储视频文件。

### 文章

文章使用 Markdown 编写，至少包含标题、摘要、日期和分类。文章封面由独立媒体用途目录提供，不写在文章正文中。

## 部署说明

当前版本依赖本机媒体服务，不能作为纯静态网站直接部署。

可接受的运行方式：

- 家庭电脑或 NAS 运行 Nuxt 服务
- 使用 Cloudflare Tunnel 或 Tailscale 提供 HTTPS 访问
- 保持照片目录在线并配置定期备份

如果希望网站脱离家庭电脑独立运行，需要进入下一阶段：

- MySQL 保存结构化业务数据
- uniCloud、COS、OSS 或 NAS 保存媒体文件
- 独立 API 负责鉴权、图片转换和访问签名
- 云端部署前端页面和媒体服务

详细方案已经写入“文字记录”中的项目建议文章。

## 隐私与安全

- 家庭照片不是普通公开素材
- 不能只依赖隐藏链接保护照片
- 数据库和对象存储密钥不能暴露给浏览器
- 图片访问应由服务端鉴权
- 共用设备上应谨慎开启 PWA 离线缓存
- 原图与数据库都需要独立备份

优先建议建设 MySQL 数据层，其次增加家庭登录、后台管理、统一媒体服务和云端或混合存储。
